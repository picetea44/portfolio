AI의 응답을 실제 입력으로 연결하기 전에,
허용된 계약과 현재 화면을 확인합니다.

지원서의 입력 항목은 서비스마다 다르고 화면도 동적으로 바뀝니다. 분석 결과가 요청한 항목과 일치하는지 검증하고, 입력 시점에 화면과 기존 값을 다시 확인하는 흐름을 구현했습니다.

→

→
APPLY화면 상태 재확인

기존 입력 보호

  • 계약 검증DTO · 서비스 · 공급자 책임을 분리하고 후보 ID, 버전, 스냅샷을 검증했습니다. 누락된 매칭은 NoMatch로 다루되 외부 응답 계약은 유지했습니다.
  • 입력 안전성공통 정책과 화면 어댑터를 구현하며 동적 입력 항목, 화면 변경, 이미 입력된 값과 실행 중단을 고려했습니다.
  • 빌드 개선ARM64 Docker 빌드에서 CI가 만든 JAR를 재사용하고 BuildKit 캐시를 적용해 중복 Gradle 빌드 경로를 줄였습니다.
구현의 판단과 검증 자세히 보기

유효하지 않은 결과를 다음 단계로 흘려보내지 않기

분석 API에서는 알 수 없거나 중복된 후보 ID, 요청과 다른 스냅샷을 검증합니다. 공급자 오류나 불완전한 응답을 성공한 분석처럼 취급하지 않도록 실패 경로를 구분했습니다.

실행 시점에도 조건을 다시 확인하기

Greeting 공통 정책과 TypeScript 입력 어댑터에서 기존 값 보호, DOM 변경 감지, 입력 결과 재확인 흐름을 다뤘습니다. 분석 시점의 정보만으로 현재 화면을 단정하지 않도록 했습니다.

검증 근거

분석 API의 정상·오류 응답을 fake ChatModel, MockMvc, Mockito 기반 테스트로 다뤘고, 화면 어댑터의 변경·중단 경로 테스트를 작성했습니다. 관련 구현과 테스트는 아래 PR에서 확인할 수 있습니다.

빌드 개선은 JAR 재사용과 캐시 적용이라는 변경을 기준으로 설명합니다. 개선 이후의 시간 단축 수치는 별도로 제시하지 않았습니다.
